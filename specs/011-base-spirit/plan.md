# Implementation Plan: Base Spirit Designation

**Branch**: `011-base-spirit` | **Date**: 2026-05-17 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/011-base-spirit/spec.md`

## Summary

Add an optional `is_base_spirit` boolean to the `Ingredient` model so recipe authors can designate one ingredient as the base spirit. The flag is stored inline on the ingredient sub-document in both SQLite (JSON blob) and DynamoDB. The frontend enforces single-select behaviour via JavaScript mutual-exclusion logic in the recipe form. The designated ingredient is highlighted with bold text and an amber `(base spirit)` label in the ingredient hover popover (RecipeCard) and the recipe detail page (IngredientList). No new API endpoints or database migrations are required.

## Implementation Phases

### Phase 1: Backend Model Change (Blocking)

Add `IsBaseSpirit bool \`json:"is_base_spirit,omitempty"\`` to `model.Ingredient`. Add `BaseSpirit bool \`dynamodbav:"is_base_spirit,omitempty"\`` to `ingItem` in `dynamo/recipes.go` and update the `toItem`/`fromItem` mapping functions. SQLite store requires no code change (JSON blob is decoded via the updated struct).

### Phase 2: Frontend — Recipe Form (US1)

Add a base spirit toggle (styled checkbox) to each ingredient row in `RecipeForm.js`. On check: clear all other rows' base spirit state. On uncheck: leave all rows clear. On prefill (editing existing recipe): restore the `is_base_spirit` state on the correct row. Include the `is_base_spirit` field when building the ingredients payload on submit.

### Phase 3: Frontend — Popover Highlight (US2)

In `RecipeCard.js → buildIngredientPopover()`, when rendering each ingredient `li`, check `ingredient.is_base_spirit` and apply bold + amber label if true.

### Phase 4: Frontend — Detail Page Highlight (US3)

In `IngredientList.js`, when rendering each ingredient `li`, check `ingredient.is_base_spirit` and apply the same visual treatment as the popover (consistency FR-008).
